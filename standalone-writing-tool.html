This tool is one self-contained web page. No server, no account, nothing you type leaves the device unless you export it yourself.

Back up & move projects

Projects save automatically in this browser's storage on this device only — clearing browser data or using a private tab can erase them, so export regularly.

On iPhone / iPad, Export opens the share sheet — tap Save to Files and choose a folder (for example iCloud Drive or On My iPhone). The file is named like writing-tool-your-project-2026-11-01.json, so searching Files for “json” or “writing-tool” finds it. If you close the share sheet without saving, no file is saved. Where file sharing isn't available, Export starts a download instead — look in Files › Downloads. Move a project: Export on one device → save the file to Files / iCloud Drive → open this tool on the other device → Import. Importing never overwrites: a project with the same name arrives as a copy.

Reference sheets for Evernote

This tool holds the skeleton only — there is no prose field. Draft prose in Evernote, using one of these Markdown sheets for the current project. Both open the same share sheet / download flow as the JSON exports above.

Overall story sheet — one sheet for the whole story: premise, key question, theme, framing, characters, the Seven-Point map, then every scene in order — grouped under chapter headings when you have set a Chapter on scenes.

Scene sheets — one section per scene to copy into its own Evernote note. Stage instructions appear in [brackets] with a blank space underneath for your prose, so you can delete the brackets or keep them above the prose. Copy finished scenes together into a chapter note in Evernote, then paste a chapter into your publishing tool.

Set the optional Chapter field on a scene (for example “Chapter 1”) to group scenes for assembly. Leave it blank if you are not grouping yet — scenes then stay in plain scene order.

Use it on your iPad (or phone) like an app

  1. Open this page in Safari on the iPad.
  2. Tap the Share button (square with an arrow pointing up).
  3. Scroll and tap Add to Home Screen, then Add.
  4. It now opens full-screen from its own icon, and works offline once loaded. Your projects stay in that device's browser storage — Export a backup before switching devices or clearing Safari data.

Works offline — planes included

This tool is client-side only: it makes no server calls, needs no account, and everything you type is saved in this browser on this device. Once the page has loaded, editing, saving, and Export (share sheet / Save to Files) all work with no connection — including in airplane mode.

  1. Open the site once while online so the whole page loads.
  2. Add it to your Home Screen (Share → Add to Home Screen) and open it from that icon.
  3. After that it opens and works offline — write on the plane, export when you land.

About service workers: this tool ships as a single self-contained HTML file, so it can't install a separate service-worker file; the home-screen copy iOS keeps after an online load is what makes offline work. If a fresh offline load ever fails, connect once, reopen the site online, then reopen it from the home-screen icon — that refreshes the copy. Your projects are never uploaded anywhere; they only move when you Export them yourself.

Host your own copy (optional)

You only need this if you want your own web address for the tool, reachable from any device without Muse. The tool is a single index.html file — ask for the exported HTML file of this page, then pick either host:

Easiest — Netlify Drop (no account setup up front, ~2 minutes):

  1. On a computer, put the index.html file in a new folder (any name).
  2. Go to app.netlify.com/drop and drag the folder onto the page.
  3. Netlify gives you a web address (like your-name.netlify.app). Open it on any device, then Add to Home Screen as above. Create a free Netlify account to claim and keep the address.
  4. To update the tool later, drag the new folder onto the same site in your Netlify dashboard.

GitHub Pages (free, if you already use GitHub):

  1. Create a new public repository, e.g. writing-tool.
  2. Upload index.html to the repository (Add file → Upload files).
  3. In the repo: Settings → Pages → Source: “Deploy from a branch”, branch main, folder / (root) → Save.
  4. After a minute your tool is at https://your-username.github.io/writing-tool/.

Either way, hosting only serves the empty tool — your stories are never uploaded. They live in each device's browser storage until you Export them yourself.

The systems behind this tool

  • Seven-Point Structure — Dan Wells (LTUE / Writing Excuses), adapted from the Star Trek Roleplaying Game Narrator's Guide.
  • Scene & Sequel — Dwight V. Swain, Techniques of the Selling Writer (1965).
  • Snowflake Method — Randy Ingermanson: sentence → paragraph → character summaries → synopsis → scene list.
  • Hero's Journey — used here only as an arc check on Seven-Point, never as a second outline.
